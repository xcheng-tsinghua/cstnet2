# Stage 1 direct baseline 共用训练流程优化

本次优化适用于 `train_stage1_direct_baseline.py` 注册的全部八种模型，不改变骨干、点数、四分量监督和 checkpoint 格式。

- 指标：在预测所在设备累计混淆矩阵和原始、最终几何误差的和及有效点数，epoch 结束合并传回 CPU。每个 batch 不再计算完整分类指标；进度条复用本次混淆矩阵计算准确率。累计张量不保留梯度，使用 float64 累计以减少长 epoch 的舍入误差。
- 损失：方向、尺寸、位置使用掩码归约，取消 Python 对 GPU `mask.any()` 的判断和变长掩码索引。先屏蔽无效标签，再计算误差，保留方向正反等价及向量三个坐标取平均的定义。没有有效点时产生零损失和零梯度。低精度误差使用 float32 归约。
- 异常检查：输出和损失各自合并检查结果，一次传回；仍然报告异常字段。梯度裁剪及更新前的梯度异常检查保留。
- 日志：loss 按样本数在设备端累计，epoch 结束合并读取；进度条从第一个 batch 起每 10 个 batch 更新一次，使用 `refresh=False`，由 tqdm 控制实际刷新。显示的是最近一次采样的 batch 数值，epoch 统计仍涵盖全部 batch。

共用属性指标函数也取消了未裁剪统计中的变长索引和方向有效性 Python 判断，保留按点云裁剪最大误差的规则。共用该函数的评估流程会同步受益。

验证：新增 CPU/CUDA 损失数值与梯度对照、空掩码、无效标签、不等长 batch、原始及最终属性、裁剪指标与异常字段检查；原有 baseline 训练、checkpoint 恢复及相关 Stage 1 回归测试通过。归约顺序变化可能带来微小浮点差异。

启动参数无需修改，正在运行的进程需要重新启动才能加载新代码。没有进行完整数据集的 epoch 计时，实际提速幅度取决于骨干、GPU 和数据读取速度。
