# Geometry 属性损失批量计算

本次优化不修改模型参数、损失权重或三阶段冻结策略，可继续加载现有 direct_mlp_v1 checkpoint。

- 实例一致性损失用 index_add/scatter_reduce 批量计算，删除逐样本、逐实例 Python 循环。
- constraint_loss 为本 batch 构造一次 (batch_id, affiliate_idx) 分组，在参数可靠性权重、尺寸、位置、几何残差和实例一致性之间复用。不同点云中相同实例编号仍分别计算。
- 属性归约改为掩码加权的批量操作，取消这些路径中的 GPU 张量布尔分支和逐实例 item()。这不表示整套训练完全没有 CPU/GPU 同步；日志和数值检查等仍有同步。

保持原有目标：单点实例不参与一致性损失，基元类别由实例内多数投票决定（平票取最小类别），方向相对于实例首点的分离梯度参考统一符号；半径使用 log1p，半角保持原单位，各有效实例/分量项仍按原规则等权平均。

测试以 tests/reference_stage1_geometry.py 保存的旧实现为数值基准，比较损失及预测张量梯度，覆盖全部基元类型、混合类别、平票、非连续实例编号、跨 batch 重号、单点实例、空有效掩码和无类型标签输入。CPU 双精度及 CUDA 单精度测试均通过。浮点累加顺序改变，结果允许正常的舍入误差，并非位级相同。

## 性能检查

```shell
python tools/benchmark_stage1_geometry_loss.py --bs 80 --n_points 2048 --instances 64 --device cuda
```

这个脚本使用合成数据，比较旧/新属性损失的前向和反向（包含新实现分组开销），不运行数据读取或骨干网络，也不写训练 checkpoint。`--instances` 是每个点云的合成实例数，应按实际数据调整。

本机 NVIDIA MX330，batch=8、512 点、每个点云 32 个实例，预热后 3 次计时的中位数：

| 实现 | 属性损失前向 + 反向 |
| --- | --- |
| 原实现 | 1.814090 秒 |
| 优化后 | 0.036803 秒 |

这个合成配置下损失部分约提速 49 倍，不能推断 4090 的整轮提速。实际训练还包括骨干前向、输入特征计算、数据加载和日志等开销。更新代码后需重启训练进程，原启动命令默认从本阶段 last.pth 继续训练。
